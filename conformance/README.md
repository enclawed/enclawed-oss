# Conformance

The security guarantees Enclawed makes, each with the tests that prove it.

**Verify them on your own installation:** run `enclawed conformance` (add `--json` for machine-readable output). It runs the checks below against the installed product, in its own process, with throwaway directories and a local test server. It does not read or change your configuration, does not use the network and never opens a hardware device. It prints one line per guarantee, PASS or FAIL, and exits with code 0 only when every guarantee holds.

**For developers:** `pnpm test:conformance` runs every test file listed here through the normal test routing. The list lives in [`invariants.json`](invariants.json).

## Semantics worth stating

- **What is not a replay.** A second execution of the same action that a person approves again is a new decision. So are calls covered by a standing grant the person or operator chose explicitly: "allow always" for a tool in one session, or an operator's pre-approval. A replay is the reuse of one approval for a second execution, which is always refused.
- **Re-admission.** A tool refused for drift stays refused for the rest of that admission, even if the server changes it back. A new session admits the server's tools again and pins what it then offers.
- **Residual window.** The re-check of an approved file target runs immediately before the tool runs; a change in the instant between that check and the write itself is outside what the check can see.
